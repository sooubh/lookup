LOOKUP: Technical Architecture & Project Specification

A privacy-preserving browser-agent architecture that keeps sensitive visual context on the device, sanitizes only the information needed for a task, and allows an external AI model to reason over the resulting safe context.

SIH26171Smart AutomationConcept / PrototypeWebExtension MV3
Architecture summary

LOOKUP places a local privacy enforcement layer between a browser agent and remote AI reasoning. The intended design combines adaptive capture, DOM/OCR/local-vision analysis, sensitive-data detection, redaction, a fail-closed egress gate, server-side reasoning, and local action validation.

2. Problem Statement

Browser agents need screen and webpage context to understand a task and perform actions. That same context can contain information that should not be exposed to external AI services.

Cloud AI

High reasoning capability

Remote models can provide strong reasoning, but browser context must be transmitted to them.

Fully local AI

Limited client resources

Keeping everything local reduces external exposure, but device memory, compute and battery are constraints.

The project focuses on the missing middle ground: keep privacy-sensitive perception and enforcement on the client, while using server-side AI where heavier reasoning is useful.

3. Why Existing Approaches Fall Short

A browser privacy layer cannot rely only on simple text filtering. Sensitive information may appear as normal DOM text, image text, rendered graphics, or visual regions that are not obvious from the page structure alone.

01 · DOM-only

Misses visual-only data

Information rendered inside images or visual UI regions may not exist as useful DOM text.

02 · OCR-only

Misses structure

OCR can recover text, but page semantics and relationships between elements are still important.

03 · Full-page sharing

Over-disclosure

Sending the whole screen gives the AI more information than the current task actually requires.

4. LOOKUP Solution

LOOKUP is proposed as a privacy middleware layer for browser agents. It determines what the task needs, perceives the page locally, removes or masks sensitive information, and controls what can cross the privacy boundary.

1User task→ natural-language browser objective
↓
2Local context capture→ DOM, screenshot or adaptive combination
↓
3Local privacy processing→ detect, redact and validate sensitive content
↓
4Sanitized context→ only task-relevant safe information
↓
5AI reasoning→ return structured action
↓
6Local validation & execution→ perform action inside browser

4.1 Task-Aware Privacy Firewall

Instead of masking the entire page, the privacy layer uses the current task to reason about which parts of the browser state are actually required. The goal is minimum necessary disclosure without removing useful context.

4.2 Multi-Source Local Perception

LOOKUP combines DOM structure, OCR and on-device visual analysis so that both structured and visual information can be inspected before egress.

4.3 Minimum-Context Sharing

Only sanitized regions, relevant UI elements and task-related information should cross the trust boundary. The raw browser state is not the intended input to remote AI.

4.4 Privacy Confidence Gate

When detection or policy evaluation is uncertain, the architecture uses fail-closed behavior: block transmission or require explicit user handling rather than silently sending ambiguous context.

5. User Flow

Step 1

Open & Ask

Install the LOOKUP extension and provide a task such as “Compare prices on this page.”

Step 2

Smart Capture

Capture only the context needed for the task using DOM capture, screenshot capture, or adaptive capture.

Step 3

Local Privacy Guard

Run OCR, sensitive-data detection, privacy policy checks and redaction locally before any external AI request.

Step 4

Server-Side AI

Reason over sanitized context and generate the next browser action.

Step 5

Action Decision

Return structured actions such as click, scroll, type or navigate.

Step 6

Execute in Browser

Validate the action locally, execute it inside the browser, then continue from the updated page state.

User Task ↓ Browser Agent ↓ Context Capture ↓ Local Privacy Guard ↓ Sanitized Context ↓ Server AI Reasoning ↓ Structured Action ↓ Local Validation ↓ Browser Execution ↓ Updated Page / Next Step

6. System Architecture

The architecture separates local privacy enforcement from server-side reasoning. The browser remains the trust anchor for raw visual context, sensitive-data detection, and action validation.

Main principle: the external model reasons over sanitized context; the browser validates and executes the returned action locally.

6.1 Browser / Local Layer

The browser side contains the agentic workflow and the enforcement mechanisms that operate before and after remote reasoning.

6.2 LOOKUP Local Privacy Layer

Task Context Analyzer

Determines what information is necessary for the current task.

Local Perception

Combines local vision, OCR and DOM information.

Sensitive Detection

Finds PII, credentials, secrets and sensitive visual regions.

Privacy Policy Engine

Applies policy and risk checks before egress.

Redaction / Masking

Removes, masks or tokenizes protected information.

Privacy Egress Gate

Controls whether the sanitized payload can leave the browser.

6.3 Trust Boundary: The architectural guarantee is that raw screenshots, PII, credentials and secrets are processed locally and are not intended to cross the boundary toward external AI.

6.4 Server AI

The server-side VLM/LLM receives the sanitized context, reasons about the task and produces a structured action that is returned to the browser for local validation.

8. Privacy Model

The design is based on minimum disclosure: do not transmit information merely because it is available. First determine what the task needs, then share the minimum safe context required to perform that task.

Stays on device

  • Raw screenshots
  • PII / personal data
  • Credentials and secrets
  • Sensitive visual regions

Sent to AI

  • Sanitized context
  • Relevant UI elements
  • Required visual regions
  • Task-related information
Fail-closed behavior: when privacy safety cannot be confidently established, the proposed architecture blocks the transmission path or requires explicit user handling rather than silently forwarding ambiguous context.

9. Agent Execution Loop

LOOKUP is designed around an iterative loop rather than a one-shot request. After each action, the browser state changes and the next step can be analyzed under the same privacy controls.

TASK ↓ PLAN → NAVIGATE ↓ CAPTURE RELEVANT CONTEXT ↓ LOCAL PRIVACY ANALYSIS ↓ SANITIZE + EGRESS CHECK ↓ SERVER REASONING ↓ STRUCTURED ACTION ↓ LOCAL ACTION VALIDATION ↓ EXECUTE IN BROWSER ↓ UPDATED PAGE STATE ↺ NEXT AGENT STEP

10. Feasibility

Challenge / riskMitigation strategy
Device limitations — larger vision models can increase memory, latency and battery use.Use lightweight / quantized models, process relevant regions and retain a WASM fallback.
Browser differences — WebGPU behavior and browser APIs can vary.Use feature detection and browser-specific fallbacks.
Privacy accuracy — false negatives can expose data; false positives can reduce usability.Combine DOM, OCR and vision signals and fail closed when detection is uncertain.
Extension constraints — MV3 service workers have DOM-access limitations.Use content scripts / offscreen processing and keep privacy logic independent from the AI layer.

11. Viability

Deployment

Browser extension model

The privacy layer can be packaged with the browser-agent workflow rather than requiring a new browser runtime.

Model independence

Replaceable AI backend

The privacy enforcement layer is conceptually separated from whichever VLM/LLM performs remote reasoning.

Scalability

Task-oriented pipeline

The architecture can be applied across different browser-agent workflows where sensitive context needs controlled disclosure.

12. Impact & Benefits

Privacy & security

Sensitive visual data is processed locally before external AI access.

Useful AI on resource-limited devices

Lightweight local processing protects sensitive content while server AI can perform heavier reasoning.

Broader AI adoption

The model supports privacy-aware browser automation for pages containing sensitive information.

Reduced unnecessary sharing

Only the task-relevant sanitized context is intended to be transmitted.

Potential efficiency improvements are workload-dependent. Local filtering may reduce unnecessary visual data sent to the server, but actual savings depend on model size, task complexity and network usage.

13. Unique Value Proposition

01

Minimum-Disclosure Context

Dynamically pass only the safest task-relevant browser context.

02

Multimodal Privacy Guard

Combine DOM, OCR and local vision to protect both structural and visual information.

03

Drop-In Agent Privacy

Add privacy enforcement around browser-agent workflows without replacing the entire agent architecture.

16. Project Status & Scope

Important: this website documents the project idea, proposed architecture, intended workflow and technical direction. It should not be interpreted as proof that every end-to-end component is currently production-ready or fully operational.

The GitHub repository already contains the LOOKUP browser-agent codebase and extension-oriented project structure. The documentation here intentionally separates the proposed system architecture from the current implementation maturity.

That distinction is important for technical reviewers: the site explains what LOOKUP is designed to achieve and how it is intended to work, without inventing benchmarks, accuracy numbers, deployment claims or completion status.
